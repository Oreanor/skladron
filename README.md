# Skladron

Браузерная игра про строительство базы и защиту от налётов дронов. Игрок размещает и улучшает оборонительные установки, управляет складом и экономикой, планирует атаки, проходит миссии и соревнования. Бой можно просматривать как повтор; отдельный режим разведки помогает изучить базу противника.

Интерфейс доступен на 13 языках: английском, русском, испанском, португальском, французском, немецком, итальянском, украинском, польском, турецком, китайском, японском и корейском.

## Требования

- Node.js и npm
- Supabase нужен для облачных аккаунтов и общего серверного состояния. Для локальной игры он необязателен.

## Запуск локально

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). Без переменных Supabase игра работает автономно, а состояние хранится в `localStorage` браузера.

Чтобы включить облачное сохранение, скопируйте `.env.local.example` в `.env.local` и укажите URL проекта Supabase и публичный anon key:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://<project>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon-key>
```

При включённом Supabase вход выполняется через Google. Настройте Google OAuth в Supabase и добавьте адрес приложения в разрешённые URL перенаправления. Для новой базы выполните `supabase/schema.sql` в Supabase → SQL Editor. Инструкции по обновлению уже существующей базы, патчам и разовым операциям находятся в [supabase/README.md](supabase/README.md).

Переменные Telegram-бота в `.env.local.example` необязательны и нужны только для уведомлений. Секреты сервера (например, токен бота и service role key) нельзя публиковать в клиентских переменных `NEXT_PUBLIC_*`.

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запустить сервер разработки Next.js |
| `npm run build` | Собрать приложение для production |
| `npm run start` | Запустить production-сборку |
| `npm run lint` | Проверить код ESLint |

## Устройство проекта

- `app/` — страницы Next.js и серверные API-маршруты.
- `components/` — интерфейс игры, лобби, карта, панели и диалоги.
- `lib/` — игровая модель, экономика, бой, повторы, Supabase и локализация.
- `lib/sims/` — сохранённые версии симуляции, нужные для воспроизведения старых боёв.
- `scripts/` — проверки и инструменты проекта.
- `supabase/` — схема базы, патчи и разовые SQL-операции.
- `public/` — изображения, звуки и прочие статические ресурсы.
- `docs/` — дизайн-документ и промо-арт.

При изменении правил, влияющих на результат боя, перед поднятием `SIMULATION_VERSION` сохраните текущий движок командой `node scripts/freeze-sim.cjs`. Серверная версия боя в Supabase должна совпадать с `SIMULATION_VERSION` в `lib/tuning.ts`; порядок обновления базы описан в [инструкции Supabase](supabase/README.md).

## Развёртывание

Приложение рассчитано на Next.js и содержит API-маршруты для разрешения боёв, ежедневного начисления дохода и интеграции с Telegram. Укажите переменные окружения production в настройках хостинга. Для планового дохода настройте вызов `/api/cron/income` согласно конфигурации проекта (`vercel.json`).
